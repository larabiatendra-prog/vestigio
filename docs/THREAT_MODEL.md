# THREAT_MODEL — Modelo de amenazas

Amenazas relevantes para una biblioteca offline personal portable. Cada una tiene mitigación de diseño y prueba exigible. Las pruebas se implementan en el bloque responsable (ver `REQUIREMENTS.md`).

| ID  | Amenaza                                                                     | Mitigación                                                                                                                                                   | Prueba                                                                                                   |
| --- | --------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------- |
| T01 | Sustitución del manifiesto o del catálogo por uno falso                     | Manifiesto superior firmado offline (Minisign/Ed25519); clave privada fuera de la entrega; fingerprint conocido-bueno documentado en papel                   | Verificación con manifiesto alterado → rechazo explícito                                                 |
| T02 | Downgrade: reemplazar la entrega por una versión antigua firmada            | Tres versiones visibles y fechadas; notas de versión; Doctor muestra versión y fecha de firma                                                                | Ensayo de downgrade → el usuario ve versión/fecha antigua y la guía lo advierte                          |
| T03 | Corrupción silenciosa del soporte (bit rot, USB defectuoso)                 | SHA-256 por archivo; verificación en Doctor y al copiar; dos copias en soportes distintos                                                                    | Corromper bytes de un asset → Doctor lo detecta y señala el archivo exacto                               |
| T04 | Fallo total del soporte                                                     | Redundancia: copia de trabajo + dos copias verificadas, una desconectada; BagIt para transferencia                                                           | Ensayo de restauración completa desde la segunda copia                                                   |
| T05 | Contenido malicioso en documentos (PDF/EPUB/HTML/ZIM con scripts o enlaces) | Saneado en construcción; lectores sin scripts; PDF.js endurecido; ZIM confinado a `WebContentsView` aislado sin IPC; CSP estricta                            | Fixtures maliciosos (script en EPUB/HTML, PDF con JS) → neutralizados; test de aislamiento del visor ZIM |
| T06 | Kiwix o Node fuera de política (escuchar en LAN, salir a Internet)          | Kiwix ligado a 127.0.0.1 con `--blockexternal`; main como único cliente loopback; `session.webRequest` + fuses; captura de red a nivel de SO como aceptación | Ensayo con captura de red del SO: cero paquetes externos durante uso completo                            |
| T07 | Dos procesos escribiendo la base personal (crash + relanzamiento)           | Supervisor con lease/epoch; no se crea sucesor sin confirmar muerte y liberar lease; un solo escritor por diseño                                             | Test de crash del `utilityProcess` durante escritura → sin segundo escritor, sin corrupción              |
| T08 | Consulta patológica (FTS gigante, booleanos profundos, regex hostil)        | Límites de longitud, operadores, profundidad, tiempo y resultados; escapado de entrada; modo avanzado validado                                               | Suite de consultas patológicas → respuesta acotada, sin cuelgue                                          |
| T09 | Divergencia entre pantalla, fallback e impresión del contenido crítico      | Fuente canónica única; fallback e imprimibles generados desde los mismos datos                                                                               | Test de igualdad de contenido crítico entre las tres salidas en cada build                               |
| T10 | Fuente comprometida durante adquisición (descarga manipulada)               | Hash y URL registrados en la ingesta; preferencia por fuentes oficiales; los originales se conservan intactos para re-verificación                           | Auditoría de manifiesto de adquisición; re-verificación de hashes contra el original conservado          |
| T11 | Pérdida/robo del soporte con datos personales                               | `USER_DATA` separado y documentado; si se necesita confidencialidad, BitLocker To Go/VeraCrypt documentados (sin cripto propia)                              | Guía verificada de cifrado del soporte; test de que la app funciona desde unidad cifrada montada         |
| T12 | Clave de firma comprometida o perdida                                       | Ceremonia de firma documentada; clave de prueba separada de la de producción; plan de rotación/revocación con re-firma y aviso en guía de recuperación       | Ensayo de rotación: nueva clave, re-firma, verificación cruzada documentada                              |

## Fuera de modelo

Atacante estatal dirigido, manipulación física sofisticada del hardware, y confidencialidad fuerte sin cifrado de soporte. Se documentan como límites honestos en la guía de usuario.
